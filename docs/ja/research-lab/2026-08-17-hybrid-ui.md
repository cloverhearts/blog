新しいインターフェースが登場するたびに、以前の方式は消えるように見えます。コマンドラインの後にGUIが広がったときも、自然言語でプログラムを操作できるようになった今も、似た予測があります。

しかし実際の変化は、完全な置き換えより役割の再配置に近いことが多くあります。AI時代のGUIも、消えるのではなく役割を変える可能性があります。

## GUIは選択肢を見せる

GUIの利点は、利用者がすべてを覚えなくてもよいことです。画面のボタンやメニューから可能な操作を発見し、現在の状態も比較的簡単に確認できます。

一方、複数の画面を移動して同じ操作を繰り返し、複雑な目標を小さなクリックに分解しなければならない弱点があります。

## LUIは意図を直接伝える

LUIは言語を基盤にしたユーザーインターフェースです。メニューを探す代わりに、望む結果を文章で伝えます。複数の手順をまとめ、普段の言葉から始められます。

しかし空の入力欄は機能を見せません。依頼が曖昧なら結果も不安定になり、AIが何を変えたか分かりにくいことがあります。自然言語は表現の壁を下げますが、判断の責任まではなくしません。

## 最終的に残るのはHybrid UI

Hybrid UIでは、利用者が言葉で目標を伝え、画面で範囲と結果を確認し、必要な部分だけ直接調整します。

例えば長い文書の構造をAIに整理させた後、変更された段落を画面で比較し、気に入らない部分だけ修正できます。言語が作業を始め、画面が作業を管理します。

| 状況 | 適した方式 |
| --- | --- |
| 何ができるか探索するとき | GUI |
| 複数の繰り返し手順を実行するとき | LUI |
| 結果を比較し微調整するとき | GUI |
| 目標は明確だが方法が分からないとき | LUIとGUIの組み合わせ |

AI時代の良い画面は、すべてのボタンを消した画面ではありません。意図を伝え、AIの行動を見て、いつでも介入できる画面です。GUIは操作盤から確認面と協働空間へ変わっていくのかもしれません。
