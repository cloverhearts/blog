Counting lines of code makes a developer’s day look simple: more lines appear to mean more work. With experience, however, it is possible to work all day and add only a few lines.

That does not mean nothing happened. Much of the work may have occurred before code needed to exist.

## Decide what does not need to be built

Before implementing a request, a developer asks whether the problem is real, whether existing behavior already solves it, whether a smaller change is enough, and who will maintain the added complexity.

Writing hundreds of lines quickly can be easier than concluding that no code is needed. The result is less visible, but it reduces the size of the system that must be maintained.

## Turn different languages into testable conditions

People describe the same feature differently. One describes a frustrating situation, another discusses schedule and cost, and another explains technical limits. A developer turns these accounts into conditions that can be checked.

This means defining success, failure, and what is outside the current scope. Without that agreement, code can grow quickly while completion keeps moving away.

## Pay for future problems in advance—but not all of them

A quick implementation can block the next change. An overly large design can make the present difficult for a future that never arrives. There is no table with a single correct answer.

Experience helps decide which complexity to accept now and which to postpone.

## Help other people move safely

Creating review criteria, explaining risky areas, and using small experiments to reduce uncertainty are also development work. A developer can prevent repeated mistakes without writing every line directly.

This does not mean implementation skills are unnecessary. Reading and writing code are needed to estimate real costs. Code is a means for making judgment real, not the final measure of value.

A developer who wrote fewer than ten lines may have created the reason that a thousand lines were unnecessary. The value appears in reduced risk and clearer decisions, not only in a line count.
