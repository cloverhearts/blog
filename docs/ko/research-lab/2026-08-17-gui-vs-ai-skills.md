버튼을 눌러 처리하던 일을 자연어로 시킬 수 있게 되면서 화면은 곧 사라질 것처럼 이야기되곤 합니다. 반복 작업을 AI Skill로 옮기면 한 문장으로 여러 단계를 처리할 수 있으니 당연히 더 빠를 것 같았습니다.

하지만 실제 작업 흐름을 비교해 보면 결론은 단순하지 않습니다. AI Skill은 반복되는 복합 작업에서 강했고, GUI는 현재 상태를 살피고 예외를 다루는 데 강했습니다.

## 무엇을 기준으로 비교할 것인가

효율을 클릭 수로만 재면 AI가 거의 항상 유리합니다. 하지만 실제 작업에서는 속도 외에도 정확도, 누락, 학습 비용, 복구 가능성을 함께 봐야 합니다.

| 기준 | GUI | AI Skill |
| --- | --- | --- |
| 처음 배우기 | 보이는 항목을 탐색하기 쉽다 | 무엇을 요청할 수 있는지 알아야 한다 |
| 반복 작업 | 같은 조작을 되풀이해야 할 수 있다 | 정해진 절차를 한 번에 실행하기 좋다 |
| 현재 상태 확인 | 화면에서 즉시 확인하기 쉽다 | 결과 보고가 부실하면 놓치기 쉽다 |
| 예외 처리 | 사용자가 상황을 보고 우회할 수 있다 | 예외 규칙이 준비되지 않으면 멈춘다 |
| 복구 | 실행 전후 상태가 보이는 편이다 | 변경 범위와 되돌리기 설계가 필요하다 |

## AI Skill이 특히 잘 맞는 일

입력과 출력의 형태가 비교적 일정하고, 중간 단계가 반복되며, 완료 조건을 문장으로 설명할 수 있는 작업은 AI Skill과 잘 맞습니다. 매번 같은 규칙을 다시 떠올리지 않아도 된다는 점도 큽니다.

반대로 결과를 보며 취향을 조절하거나 화면 곳곳의 상태를 한눈에 비교해야 하는 일은 GUI가 편합니다. 자연어로 상태를 여러 번 묻는 것보다 눈으로 확인하고 한 번 조정하는 편이 빠른 경우가 많습니다.

## 숨은 비용은 ‘요구 조건을 쓰는 일’이다

AI Skill은 사용자의 말을 알아서 완성해 주는 마법 상자가 아닙니다. 좋은 결과를 내려면 입력 조건, 금지 사항, 실패했을 때의 행동, 완료 기준을 정해야 합니다. 개발자가 아닌 사람에게도 작은 사양서를 쓰는 능력을 요구하는 셈입니다.

GUI는 가능한 행동을 화면에 펼쳐 보여 줍니다. AI Skill은 화면을 줄이는 대신 가능한 행동을 머릿속에 넣어 두게 합니다. 이 차이는 생각보다 큽니다.

결국 질문은 “어느 쪽이 더 발전된 인터페이스인가”가 아닙니다. 어떤 업무를 반복하고 있으며, 어디서 판단이 필요하고, 실패했을 때 어떻게 알아차릴 것인가가 먼저입니다. 반복 절차는 AI Skill에 맡기고 상태 확인과 예외 판단은 GUI로 남기는 조합이 지금으로서는 가장 현실적입니다.
